# Stock Transformer model audit

## Scope and current data flow

`backend/app/data.py` fetches daily Yahoo Finance `Close` data for INFY.NS and HINDUNILVR.NS. `features.py` builds nine causal features (daily log return, two lagged returns, 20-session volatility and mean return, RSI-14, distance from MA-50, and weekday encoding). Each sample contains 20 rows of features. `target_ret` is the next row's log return. `make_sequences` assigns the forecast date to that next row and carries the last observed close as its price anchor.

`model.py` is a two-layer, 64-wide Transformer encoder with a scalar regression head. `train.py` scales features and return targets using the first 80% of pre-2025 sequences, selects the best epoch on the chronological final 20%, and reports 2025 onward as the test. A separate scikit-learn direction classifier is selected on the same chronological 80/20 pre-test split and refit using all pre-2025 samples. The final price prediction uses the Transformer's absolute return magnitude and the classifier's sign.

The regression MAE/RMSE and R² are calculated on reconstructed close prices. R² uses variation around the test-period mean close, so it can be high when the model follows the price level while still missing the sign of daily returns. Directional accuracy compares the classifier class with `next_log_return > 0`; it is not the Transformer's raw sign accuracy. The dashboard currently labels that split/model incompletely and has no aligned reference models.

## Confirmed findings

- **Target alignment is internally consistent for one session.** A feature window ending at session *t* is paired with log(Close[t+1]/Close[t]); the stored anchor is Close[t]. The target price reconstruction therefore uses information available at the forecast origin.
- **The split is chronological and the current classifier does not select on test labels.** Its scaler is fit on the classifier's training slice, then the selected estimator refits through 2024. The test starts 2025-01-01.
- **The evaluation payload is real Yahoo Finance data and currently contains 465 dates through 2026-11-17** for each ticker, fetched from price data ending 2026-11-18.
- **The R² is on price levels, not returns.** It should never be used by itself as evidence of directional or trading value.
- **The Transformer's fitted checkpoint excludes the latest 20% of pre-2025 samples.** Those samples are used for early stopping but are not added back before the final fit; the classifier does refit through 2024. This leaves several years unavailable to the regression fit.
- **Baseline and classification diagnostics are absent.** No persistence/mean/linear regression comparisons, majority/logistic comparisons, balanced accuracy, confusion matrix, class counts, or uncertainty interval are persisted.
- **The current fixed-parameter test forecast is not a refit-at-each-origin walk-forward.** The feature window advances daily, but fitted parameters remain fixed from pre-2025. UI copy should call this a fixed-origin, rolling-input holdout unless a true expanding refit is run.
- **There is no transaction-aware backtest.** Accuracy alone says nothing about executable or profitable performance. Close-only data also cannot model opening fills; any diagnostic must delay execution and disclose that limitation.
- **The dashboard does not identify target/horizon/sample count for each displayed metric**, and it omits directional baselines and error breakdowns.

## Risks and recommended controls

- Keep all model selection, scaling, target thresholds, and confidence-bin definitions within training/validation data. Preserve the final chronological test as a one-time report.
- Compare all direction models against the same test dates and explicitly include the always-up/majority rule. Show confidence intervals because 465 observations leave substantial sampling uncertainty.
- Evaluate close forecasts against persistence and a simple training-fitted regression. Report returns-based classification metrics separately from close-level regression metrics.
- Use an expanding-origin, delayed-execution backtest as a diagnostic only. Close-only data and assumed costs cannot establish deployable profitability.
- Treat neutral thresholds, volatility normalization, and alternative return targets as validation-selected experiments. Keep a final untouched period for the winner.
- Guard against older checkpoint schemas and clearly reject non-real checkpoint/data sources in the live route.

## Existing test artifacts before this audit

The pre-audit artifacts report INFY R² 0.9892 / DA 48.82% and HUL R² 0.9766 / DA 54.41% for the 2025-01-01 to 2026-11-17 holdout. These are the classifier-sign-plus-Transformer-magnitude system's results, not raw Transformer direction results. They are historical artifacts; newly added diagnostics must be generated by the corrected evaluator before being presented as current comparative results.

## Post-audit implementation and observed results

The evaluator now exports same-date regression and direction baselines, target/horizon/split/sample metadata, actual class counts, balanced accuracy, up precision/recall/F1, MCC, confusion matrices, confidence-rank buckets, a predeclared three-class experiment, and a delayed close-only long/flat diagnostic. The Transformer epoch is selected using a chronological validation tail, then a fresh final model is fitted on all pre-test samples for the selected number of epochs. The final x/y scalers are fitted only on that complete pre-test training set.

Period: 2025-01-01 to 2026-11-17, 465 sessions each. The best naïve rate is the better of always-up and the training majority rule. INFY's standalone logistic direction baseline scored 51.83% and the expanding logistic baseline 51.18%; these test comparisons are reported for transparency and were **not** used to change the validation-selected model. The combined INFY forecast does not beat previous-close persistence on MAE. HUL improves persistence MAE by about ₹0.05.

The delayed long/flat diagnostics had cumulative returns of -35.14% (INFY) and -21.58% (HUL), versus buy-and-hold -39.89% and -13.62%, respectively, under the stated 10bp-per-turnover-unit cost. Both Sharpe ratios were negative. The strategy is not evidence of profitability.

Directional-accuracy intervals in the payload use the Wilson binomial interval. They assume independent observations; because daily outcomes can be serially dependent, these intervals may be too narrow. This assumption is stated in the dashboard.

Added tests cover one-step target alignment, the live feature tail, missing-close rows, chronological split order, train-only scaler bounds, metric/confusion calculations, baseline-suite consistency, delayed execution, and loading/determinism of a saved real-data direction checkpoint. The test suite passed during this implementation. Frontend lint and production build also passed. A multi-task Transformer was not added: the measured simple baselines and the tested separate classifier provide a useful comparison without adding an unvalidated architecture.
